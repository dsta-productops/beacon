This tutorial follows one example project, SKYPROTECT, from raw interview notes to a prototype that real users can test. You do not need a background in product management or design.

By the end you will have:

- **Research documents**, each traced to its sources (steps 5, 7, 8, 9)
- **A requirements document** (PRD) (step 10)
- **A working prototype** built with PRIZM (step 11)
- **A test plan** (step 12)
- **A baseline and test results** to compare against (steps 6, 13)

## 1. Check the prerequisites
::step{id="prerequisites" phase="Setup"}

Confirm you have the access you need before you start.

- A GitLab account that can create projects. To use your own wiki later, you need the Developer role or above on it.
- Access to [DASH](/tools/dash), at [diux-dash.com](https://diux-dash.com).

:::watch{title="Read this first"}
- Use the Claude Code plugin in your IDE, such as VS Code. The command-line version and the desktop app do not work with this tutorial.
- Never paste a token or password into a chat. Use the git credentials already on your machine.
- CLARA builds on what you give it, so an early mistake carries through every later step. Check each result before you move on.
- If a document lands in the wrong place or cites nothing, stop and check that the Knowledge Base from step 4 exists and your source links point to real pages.
:::

## 2. Install your tools
::step{id="workspace" phase="Setup" tool="Git + VS Code"}

Set up a workspace and a GitLab wiki for the tutorial. Allow about 20 minutes. Skip any tool you already have.

#### Install VS Code, Claude Code and git

1. Install **VS Code** from [code.visualstudio.com](https://code.visualstudio.com).
2. In VS Code, open the Extensions view, search for **Claude Code** and choose **Install**. Sign in from the Claude panel.

::screenshot{src="/gitlab-walkthrough-1.png" alt="VS Code Extensions view with Claude Code for VS Code selected and its Install button" caption="VS Code Extensions view, with Claude Code and its Install button" hint="the VS Code Extensions view with Claude Code in the results and the Install button visible, then the Claude panel signed in"}

3. Create a folder such as `skyprotect-workspace`, then choose **File > Open Folder**.
4. Open the terminal: choose **Terminal > New Terminal** in VS Code. A panel opens at the bottom of the window, where you type commands and press :kbd[Enter] to run them. It looks different on Windows and Mac, but it works the same way.

::screenshot{src="/gitlab-walkthrough-2.png" alt="VS Code with the Terminal menu open and the terminal panel at the bottom" caption="The terminal panel open at the bottom of VS Code" hint="VS Code with the terminal panel open at the bottom of the window"}

5. Install **git**:
   - **Windows:** download it from [git-scm.com](https://git-scm.com/downloads) and run the installer, keeping the default options. Then close the terminal panel and open a new one.
   - **Mac:** type `git --version` in the terminal and press :kbd[Enter]. If a window asks you to install the developer tools, choose **Install**.
6. Type these two commands in the terminal, pressing :kbd[Enter] after each. Use your own name and email:
   ```prompt
   git config --global user.name "Your Name"
   ```
   ```prompt
   git config --global user.email "you@example.com"
   ```

#### Create the GitLab project and wiki

1. In GitLab, choose **New project > Create blank project**. Name it **SKYPROTECT** and untick the **Initialize repository with a README** checkbox.

::screenshot{src="/gitlab-walkthrough-3.png" alt="GitLab Create blank project form with the project name SKYPROTECT" caption="The Create blank project form, with the README checkbox unticked" hint="the Create blank project form with the project name SKYPROTECT and the Initialize repository with a README checkbox unticked and highlighted"}

2. Open **Plan > Wiki** and choose **Create your first page**. Set the title to `home`, add any placeholder text and save. Add no other pages.
3. Choose **Clone repository** and copy the HTTPS address. It ends in `.wiki.git`.

::screenshot{src="/gitlab-walkthrough-4.png" alt="GitLab wiki Home page with the page menu open and Clone repository highlighted" caption="The wiki's Clone repository menu, with the HTTPS address ending in .wiki.git" hint="the SKYPROTECT wiki page with the Clone repository button open and the HTTPS address ending in .wiki.git highlighted"}

:::check
VS Code is open on an empty folder, the Claude panel answers, the SKYPROTECT wiki holds one `home` page, and the wiki clone URL is copied.
:::

**If `git` is not found:**
- Close the terminal and open a new one. If it still fails, repeat the git install for your system.

**If git asks who you are:**
- Run the two `git config` commands again.

**If git asks you to sign in:**
- Sign in through the browser window or terminal prompt.
- If it asks for a token, create a personal access token with the `write_repository` scope and type it only into that prompt.

## 3. Install CLARA
::step{id="install-clara" phase="Setup" tool="CLARA"}

CLARA is a **skill**: a Markdown file that tells Claude how to draft research documents and file them in your wiki.

Choose one method.

:::::tabs
::::tab{value="file" label="File method"}
Install CLARA once and it is available whenever you open this workspace.

1. Download :file[SKILL.md]{href="/gitlab/SKILL.md"}.
2. In your IDE's file list, create the folders `.claude/skills/clara-gitlab`.
3. Drag the downloaded file into `clara-gitlab`. Keep the name as it is.

::screenshot{src="/gitlab-walkthrough-5.png" alt="VS Code showing .claude/skills/clara-gitlab/SKILL.md in the file list" caption="The folder .claude/skills/clara-gitlab, holding SKILL.md" hint="the IDE file list showing .claude/skills/clara-gitlab with SKILL.md inside"}

4. Start a new chat in the Claude panel and ask:
   ```prompt
   What can CLARA do?
   ```

**If CLARA does not appear:**
- Check that the folder is named `clara-gitlab`, it holds `SKILL.md` (spelled exactly with capitals), and `.claude` is at the top of the folder you opened.
- Run **Developer: Reload Window** from the command palette.

**Note:** To make CLARA available in every project, put the same folders in your home folder (`~/.claude/skills/clara-gitlab/`). Dot folders are hidden by default. On a Mac, press :kbd[Cmd] + :kbd[Shift] + :kbd[.] in Finder. On Windows, choose **View > Show > Hidden items** in File Explorer.
::::

::::tab{value="url" label="URL method"}

1. Open a new chat in the Claude panel and paste:


**If CLARA does not respond:**
- Check that you pasted the whole prompt.
- Open the address in your browser. If it does not load, use the file method.
::::

:::check
CLARA introduces itself and says what it can do, such as drafting personas, journeys, PRDs and test plans.
:::

CLARA loads the prompt for each document type from the DSTA ProductOps site. If it cannot reach the site, it asks you to paste the prompt. You can copy every one from the [Prompts](/prompts) page.

## 4. Set up the SKYPROTECT Knowledge Base
::step{id="knowledge-base" phase="Setup" tool="AI assistant"}

SKYPROTECT is a made-up drone-defence programme. One setup file describes its whole wiki, and your assistant builds the wiki from it.

1. Download :file[skyprotect-gitlab-setup.md]{href="/skyprotect-gitlab-setup.md"}.
2. In the Claude panel, attach the file and paste this prompt. Replace the placeholder with your wiki clone URL.
   ```prompt
   Set up the SKYPROTECT demo Knowledge Base in a GitLab wiki by following the attached setup file exactly. The wiki clone URL is <paste your wiki clone URL>. The project and its wiki already exist, so do not create them. Use plain git commands only, with the git credentials already on this machine. If anything cannot be written, committed or pushed, stop and tell me. Do not retry or improvise.
   ```

::screenshot{src="/gitlab-walkthrough-6.png" alt="Claude panel with skyprotect-gitlab-setup.md attached and the prompt pasted" caption="The Claude panel with the setup file attached and the prompt pasted" hint="the Claude panel with skyprotect-gitlab-setup.md attached and the prompt pasted, with the attach control highlighted"}

3. Wait for it to finish, then open the wiki home link it gives you.

::screenshot{src="/gitlab-walkthrough-7.png" alt="SKYPROTECT wiki home page in GitLab with the sidebar page tree" caption="The SKYPROTECT wiki home page, with the sidebar tree expanded" hint="the SKYPROTECT wiki home page in GitLab, with the sidebar tree expanded"}

:::check
The sidebar shows **Knowledge Base** with two tracks, **Programme-wide** and **Operator-console**, holding 52 pages in all, including 24 interview and field notes. Click a citation such as S08 in the research synthesis to open that note.
:::

**If the assistant stops:**
- It stops on purpose when something is wrong. Common causes are a wiki that was never initialised, no push access (you need the Developer role or above), missing git credentials, or a wrong clone URL.
- Fix the cause and run the same prompt again. Pages that already exist with identical content are skipped. The assistant never overwrites a different page, apart from your placeholder `home`.

The setup also files a finished example of most documents you make in steps 5 to 12. Compare each with your own to see what good looks like. For a real programme, ask CLARA to create the folder structure instead. See [the CLARA provisioning steps](/tools/clara#provisioning).

## 5. Find what is already known
::step{id="prior-knowledge" phase="Research" tool="CLARA"}

Review past projects and other teams' wiki pages first, so you do not start from zero.

1. Paste this prompt into CLARA:
   ```prompt
   Use CLARA's `prior-knowledge-summariser` for SKYPROTECT.
   ```
2. Answer its questions about your programme name, track and topic. Choose a specific topic, such as "how operators hand over between shifts", not "user research".
3. Give it your sources as wiki page links, one per page. Remove any that do not belong.
4. Review the path and every file CLARA says it will change, then reply **go**. CLARA files nothing until you do.

::screenshot{caption="CLARA's list of files to change, waiting for your reply of go" hint="CLARA's list of files it will change, with the prompt waiting for the reply go"}

:::check
A summary of patterns, contradictions and related work, filed under `[track]/Prior-knowledge/[topic]`. Each finding names the wiki page it came from.
:::

:::example
`Programme-wide/Prior-knowledge/Counter-drone-systems`
:::

**If the summary is thin or generic:**
- Add more source material, such as interview notes or past write-ups.
- Narrow the topic and run the prompt again. A finding with no source is a guess, not a fact.

**If CLARA cannot see your wiki:**
- Check that you can open the wiki yourself, that it is enabled, and that you have the Developer role or above.
- If it still fails, ask your CLARA contact to check its access.

**If a push is rejected or authentication fails:**
- Check that you can push to the wiki yourself. CLARA only uses the git credentials already on your machine.
- If the wiki changed, CLARA pulls, rechecks the path and retries once, then stops and tells you.

## 6. Measure how things are today
::step{id="baseline" phase="Research" tool="DASH"}

A **baseline** measures how things work today, so you can show later that your design is better. Do it before any interviews or design work.

1. Sign in at [diux-dash.com](https://diux-dash.com) and open your programme's workspace.
2. Create a session, choose **Baseline Testing**, and name the system people use today. For SKYPROTECT, that is the three-vendor toolchain of separate radar, RF and camera systems.

::screenshot{caption="The DASH new-session screen, with Baseline Testing selected" hint="the DASH new-session screen with Baseline Testing highlighted"}

3. Share the link or QR code with people who use that system.

::screenshot{caption="The Baseline Testing session, showing the share link and QR code" hint="the Baseline Testing session in DASH, showing the share link and QR code"}

:::check
Responses appear in DASH as people answer. Keep this session open, because you compare against it in step 13.
:::

**If you cannot find your programme's workspace:**
- Each programme has one DASH workspace. Ask your DASH contact to add you.

DASH asks about **SUS** (System Usability Scale, a short score for how easy a system is to use), look and feel, user needs, system performance and **CSAT** (customer satisfaction). It also tracks **OKRs**, which are goals with numbers attached.

## 7. Interview your users
::step{id="interviews" phase="Research" tool="CLARA"}

Surveys give you numbers. Interviews tell you why. CLARA writes the guide and you run the conversations.

1. Paste this prompt into CLARA, then tell it the topic and what you want to learn:
   ```prompt
   Use CLARA's `interview-guide-generator` for SKYPROTECT.
   ```
2. Run 5 to 7 conversations.
3. After each one, copy `Template-Field-note` in the track's `Field-notes` folder and paste in your notes exactly as you took them. Do not tidy them, because polished notes add your own bias.

:::check
A field-ready interview guide with questions, things to listen for and follow-up prompts. Your raw notes are in `Field-notes`.
:::

**For the SKYPROTECT demo:** do step 1 only. The 24 interview and field notes are already in `Field-notes` in both tracks.

## 8. Make sense of the notes
::step{id="synthesise" phase="Research" tool="CLARA"}

**Synthesis** pulls the patterns out of many notes. CLARA reads them all in one pass and separates what is new from what you already knew.

1. Paste this prompt into CLARA:
   ```prompt
   Use CLARA's `research-synthesiser` for SKYPROTECT.
   ```
2. Give it your learning goals and the gaps you found in step 5.

:::check
One research-synthesis page with recurring patterns, friction points, standout statements and success criteria, citing your field notes.
:::

:::example
`Operator-console/Research-synthesis` (the programme-wide version is under `Programme-wide/Research-synthesis`)
:::

## 9. Profile your users
::step{id="personas-journeys" phase="Research" tool="CLARA"}

Turn the research into three documents. Paste each prompt into CLARA in turn.

1. Create a **persona**: a profile of a typical user, with their goals, frustrations and the evidence.
   ```prompt
   Use CLARA's `persona-generator` for SKYPROTECT.
   ```
2. Create a **user journey**: the steps a person goes through, and where you could improve things.
   ```prompt
   Use CLARA's `journey-map-drafter` for SKYPROTECT.
   ```
3. Create a **service blueprint**: the journey plus what your team and systems do behind the scenes.
   ```prompt
   Use CLARA's `service-blueprint-drafter` for SKYPROTECT.
   ```

:::check
Three new pages in the Knowledge Base, each linked from its folder index and the sidebar. Every claim points back to a quote or note.
:::

:::example
`Operator-console/Personas/Console-operator` and `Operator-console/Journeys/Engage-incoming-threat`. The demo has no service blueprint, so yours is the first.
:::

## 10. Write the requirements
::step{id="prd" phase="Research" tool="CLARA"}

A **PRD** (product requirements document) is one page everyone agrees on: the problem, who it is for, what the product must do and how you will know it worked. It is the most important output of Research.

1. Paste this prompt into CLARA:
   ```prompt
   Use CLARA's `prd-generator` for SKYPROTECT.
   ```
2. Read the draft, then edit it by hand. It becomes the input for your prototype.

:::check
A PRD with a problem statement, user goals, scope, functional requirements and user stories.
:::

:::example
`Operator-console/PRDs/Console-v1`
:::

## 11. Build a prototype
::step{id="prototype" phase="Design" tool="Claude Code + PRIZM"}

A prototype is a working draft people can click through. Claude Code reads your PRD and PRIZM's rules, so the result follows DSTA standards without extra styling work.

1. Open an empty project folder in your IDE and start a chat in the Claude panel.
2. Open the [Prototype-from-PRD scaffolder](/prompts/prototype-from-prd) prompt and paste your PRD where it asks.
3. Choose a PRIZM zone: **Enterprise** for websites and back-office tools, or **C3** for command-and-control systems.

::screenshot{caption="Claude Code asking which PRIZM zone to use, Enterprise or C3" hint="Claude Code asking which PRIZM zone to use, with Enterprise and C3 as the options"}

4. When Claude Code lists three to five user flows, pick one to build first. Do not skip this question.
5. Open the prototype in your browser. To change something, describe the change in plain English.

::screenshot{caption="The running prototype in the browser, next to Claude Code" hint="the running prototype in the browser, next to Claude Code"}

:::check
A running prototype of your chosen flow, built from PRIZM components and semantic colour tokens such as `bg-bg` and `text-fg`, not raw colours.
:::

**If Claude Code invents components PRIZM does not have:**
- Stop it and ask it to check `lib/components-registry.ts` in the PRIZM repository before it generates anything more.

## 12. Plan the test
::step{id="test-plan" phase="Test" tool="CLARA"}

A test plan says who you will test with and what you will ask them to do. CLARA reads your PRD and personas to draft one.

1. Paste this prompt into CLARA:
   ```prompt
   Use CLARA's `test-plan-generator` for SKYPROTECT.
   ```
2. Review the plan and adjust the number of participants to fit your team.

:::check
A test plan with objectives, research questions, personas to recruit, participant numbers, scenarios and tasks.
:::

:::example
`Operator-console/Test-plans/Console-v1-usability-test`
:::

## 13. Test and compare
::step{id="test" phase="Test" tool="DASH"}

Test the prototype, then compare the results with your baseline from step 6.

1. In DASH, create a session and choose **Prototype Test**.
2. Share the link or QR code with your participants and run the sessions as set out in your test plan.
3. Compare the results with your baseline session.

::screenshot{caption="The DASH comparison view, baseline against prototype results" hint="the DASH comparison view, baseline against prototype results"}

4. Ask **DASH AI** for recommendations. It suggests usability improvements based on industry standards.

::screenshot{caption="The DASH AI button on the results page" hint="the DASH AI button on the results page"}

:::check
Side-by-side scores for the old system and your prototype, plus a list of suggested improvements. This is your evidence that the new design is better, or your guide to what to fix next.
:::
