This tutorial takes a project from raw interview notes to a prototype that real users can test.

You do not need a background in product management or design.

This tutorial is long, but you do not have to finish it in one go! Take it a few steps at a time.

### Choose how you will follow this tutorial

We recommend completing the demo project first, before using your own.

::projectswitch

## 1. Check the prerequisites
::step{id="prerequisites" phase="Setup"}

Confirm you have this access before you start:

- **Confluence.** An account that can create a Confluence space.
- **A Claude account.** This can be a paid Claude subscription (Pro, Max, Team or Enterprise) or a Claude Console account. Step 2 uses it to sign in to [Claude Code](/tools/claude-code).
- **INSIGHT.** Step 10 needs it, and that step is optional. INSIGHT is currently available on Mac.
- **[DASH](/tools/dash),** at [diux-dash.com](https://diux-dash.com). Steps 7 and 17 use it.
- **The [PULSE CMS](https://pulse-reportcards.vercel.app).** Step 18 needs it.

If you do not have access to DASH or PULSE, email [DESIGNINNO@dsta.gov.sg](mailto:DESIGNINNO@dsta.gov.sg) to ask for it.

## 2. Set up Claude Code
::step{id="setup-claude-code" phase="Setup" tool="Claude Code"}

From here on, you work in the **Claude panel** inside VS Code.

VS Code is a free editor that also handles ordinary files and folders.

Claude Code is the AI assistant in the panel, and it is the only one this tutorial uses.

You set up four things once: VS Code, your tutorial folder, Claude Code, and the connection that lets Claude Code read and write Confluence.

### Install VS Code

1. Download VS Code from [code.visualstudio.com](https://code.visualstudio.com/) and install it. You need version 1.94.0 or later. If your computer is managed, your IT team may need to install it for you.
2. Open VS Code.

### Create your tutorial folder

You use one folder for the whole tutorial, so that CLARA, PRIZM and your prototype are all in one place.

1. In Finder (Mac) or File Explorer (Windows), create an empty folder somewhere easy to find, such as your Documents folder. :own[Name it after your project.]:demo[Call it `beacon-tutorial`.]
2. In VS Code, choose **File**, then **Open Folder**, and select :own[the folder you just created]:demo[`beacon-tutorial`].
3. If VS Code asks whether you trust the authors of the files in this folder, click **Yes, I trust the authors**.

### Install Claude Code

1. Open the Extensions view. Press **Cmd + Shift + X** on a Mac or **Ctrl + Shift + X** on Windows.
2. Search for **Claude Code**, choose the one published by Anthropic and click **Install**.

::screenshot{src="/confluence-walkthrough-step-2-1.png" caption="VS Code Extensions view, with Claude Code and its Install button" hint="the VS Code Extensions view with Claude Code in the results and the Install button visible, then the Claude panel signed in"}

3. Click **✻ Claude Code** in the bottom-right corner of the window to open the Claude panel.
4. Click **Sign in** and finish signing in in your browser, using the Claude account from step 1.

### Connect Claude Code to Confluence

1. In the Claude panel, type `/mcp` and press Enter. This opens the list of connections.
2. Add a new connection. Name it `atlassian`, choose **HTTP** as the type and enter this address. If you are asked where to save it, choose **user**, so the connection works in every folder you open:
   ```
   https://mcp.atlassian.com/v1/mcp/authv2
   ```
3. Select `atlassian` in the list and choose to authenticate. Your browser opens. Sign in to Atlassian and approve access to your Confluence site. Claude Code can only see what your own account can see.

::screenshot{src="/confluence-walkthrough-step-2-2.png" caption="The /mcp list showing the atlassian connection as connected" hint="the Claude panel with the /mcp connection list open and the atlassian entry showing as connected, highlighted"}

4. Test it by asking:
   ```prompt
   List the Confluence spaces I can access.
   ```

:::check
Claude Code lists the Confluence spaces you connected it to.
:::

## 7. Measure how things are today
::step{id="baseline" phase="Research" tool="DASH"}

A **baseline** measures how things work today, so you can show later that your design is better.

Do it before any interviews or design work.

**DASH** asks about **SUS** (System Usability Scale, a short score for how easy a system is to use), look and feel, user needs, system performance and **CSAT** (customer satisfaction).

It also tracks **OKRs**, which are goals with numbers attached.

1. Sign in at [diux-dash.com](https://diux-dash.com) and open your programme's workspace.
2. Create a session, choose **Baseline Testing**, and name the system people use today. :demo[Name it **the current three-window toolchain: Halden Radar, Sigma RF Watch and Optix EO Viewer**.]

## 8. Review the product people use today
::step{id="heuristic-evaluation" phase="Research" tool="CLARA"}

A **heuristic evaluation** checks a product against well-known usability rules, called **heuristics**.

CLARA uses Nielsen's 10 heuristics.

For each problem it finds, it gives a severity rating and the screen it appears on.

These problems feed your research synthesis in step 11 and your problem ranking in step 13.


1. Collect the material to evaluate: numbered screenshots of the flows, a link CLARA can open, or a PDF or deck of the screens.
   :::demo
   Download :file[skyprotect-demo-screens.zip]{href="/skyprotect-demo/skyprotect-demo-screens.zip"} and unzip it.

   It holds four numbered screenshots of the current toolchain: two of Halden Radar, one of Sigma RF Watch and one of Optix EO Viewer.
   :::
2. :own[Paste this prompt into CLARA. Replace PROGRAMME with your programme's name.]:demo[Paste this prompt into CLARA:]
   ```prompt
   Use CLARA's `heuristic-evaluator` for PROGRAMME.
   ```
3. Tell CLARA the product name, then attach your material or paste the link.
   :::demo
   Attach all four screenshots, then answer with:

   ```prompt
   Programme name: SKYPROTECT
   Track: Programme-wide
   Product name: the current SKYPROTECT toolchain: Halden Radar, Sigma RF Watch and Optix EO Viewer
   Evaluation mode: an existing system being improved
   Task scenario: an operator confirms an incoming drone across the radar, RF and camera tools
   ```
   :::
:::own
4. Choose the evaluation mode: a competitor's product, an existing system you want to improve, a product being retired, or a standalone evaluation.
5. Name the one or two tasks to check, such as "an operator confirms and reports a threat". If you do not, CLARA proposes them from the screens and asks you to confirm.
:::

6. CLARA shows you the draft and the page it will go under. Say yes to file it.

:::check
In Confluence, open the **Heuristic-evaluations** folder. It holds your new report, with a score out of 100, severity-rated findings that each cite a screen, and a fix list ranked P0, P1 and P2.

## 13. Rank the problems
::step{id="problem-ranking" phase="Research" tool="CLARA"}

Your research now lists many problems, and you cannot fix them all at once.

CLARA ranks them so you know which to build for first.

It scores each problem out of 5 on four measures, so a problem scores up to 20:

- **Reach:** how many people it affects
- **Severity:** how badly it hurts
- **Evidence:** how well it is proven
- **Leverage:** whether fixing it also fixes others

1. :own[Paste this prompt into CLARA. Replace PROGRAMME with your programme's name.]:demo[Paste this prompt into CLARA:]
   ```prompt
   Use CLARA's `problem-impact-ranker` for PROGRAMME.
   ```
2. Tell it which problems to rank, such as all problems across the journey, or one track's. Name where they come from, such as the friction table in your research synthesis from step 11, so the ranking can be traced.
   :::demo
   Answer with:

   ```prompt
   Programme name: SKYPROTECT
   Track: Programme-wide
   Problem set scope: all problems across confirming and reporting an incoming drone
   Source of the problems: the friction points in the Programme-wide research synthesis, the heuristic evaluation and the field notes
   ```
   :::
3. Read the ranked table and the tiers. Check that the top problems match what you saw in the research.
4. CLARA shows you the draft and the page it will go under. Say yes to file it.

:::check
In Confluence, open the **Problem-impact-analysis** page. It has a ranked table with each problem scored out of 20, grouped into tiers. Each problem names whose pain it is and the evidence behind it.

## 15. Build a prototype
::step{id="prototype" phase="Design" tool="Claude Code + PRIZM"}

A prototype is a working draft people can click through.

Claude Code reads your PRD and PRIZM's rules, so the result follows DSTA standards without extra styling work.

1. In VS Code, with :own[your project folder]:demo[`beacon-tutorial`] open, start a new chat in the Claude panel.
2. Check that two free tools are installed. Claude Code needs them to run your prototype: **Node.js** (version 20 or later) and **pnpm**.
   :::details{title="Show me how to check and install them"}
   1. In VS Code, choose **Terminal**, then **New Terminal**. A panel opens at the bottom of the window.
   2. Type this and press Enter:
      ```
      node --version
      ```
      If it shows `v20` or a higher number, such as `v22.11.0`, Node.js is ready.

      If it says the command is not found, or shows a lower number, download the version marked **LTS** from [nodejs.org](https://nodejs.org/), install it, then close VS Code and open it again.

      If your computer is managed, your IT team may need to install it for you.

   3. Type this and press Enter:
      ```
      pnpm --version
      ```
      If it shows a number, such as `9.12.0`, pnpm is ready.

      If it says the command is not found, type this, press Enter, then run the check again:
      ```
      npm install -g pnpm
      ```
   4. Skip this part if your computer can reach the internet.

      If you are on an intranet with no internet access, pnpm cannot download what the prototype needs until you point it at your organisation's own copy.

      Ask your IT team for the address of your internal npm registry, then type this, replacing `<address>` with what they give you:
      ```
      pnpm config set registry <address>
      ```
   :::
3. Paste this prompt into the Claude panel.

   It tells Claude Code which Confluence page holds your PRD, so you do not paste the PRD itself.
   
   :::own

Use PRIZM components wherever one exists, and use semantic colour tokens, never raw colours. Do not invent components. If you need one that PRIZM does not have, tell me.

   :::
